# Kakeibo — あといくら使える？

自分専用の支出管理アプリ。
「家計簿をきれいにつける」ためではなく、**お金を使う前に「あといくら使っていいか」を確認する**ためのアプリです。

アプリを開いた瞬間に分かること:

| | |
|---|---|
| **今月あと使える金額** | いちばん大きく表示。予算超過はマイナス表示 |
| **今月の使用額 / 予算** | プログレスバーと使用率 |
| **次回クレカ引き落とし** | 締め日・支払日から自動計算 |
| **カード未払い合計** | まだ口座から落ちていない総額 |

## 起動方法

```bash
npm install
```

```bash
npm run dev
```

`http://localhost:5173` が開きます。

> **Windows の PowerShell で `npm` が使えない場合**
> 「スクリプトの実行が無効になっているため npm.ps1 を読み込めません」と出たら、
> `npm` の代わりに **`npm.cmd`** と打ってください（`npm.cmd run build` など）。
> 恒久的に直すなら `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` ですが、
> セキュリティ設定の変更になるので必須ではありません。

| コマンド | 内容 |
|---|---|
| `npm run dev` | 開発サーバー起動 |
| `npm run build` | 本番ビルド（`dist/` に出力） |

## Android で使う

このアプリは **PWA** です。ホーム画面に追加すると、ブラウザのUIが消えて普通のアプリのように全画面で開き、**圏外でも起動します**。

### 方法1: とりあえず自宅で試す

PC で LAN 配信し、同じ Wi-Fi のスマホから開きます。

```bash
npm run dev:lan
```

表示された `http://192.168.x.x:5173` にスマホの Chrome でアクセスします。

ただし **http では Service Worker が動きません**。この方法では「ホーム画面に追加」しても
**オフラインでは開けず、インストールの案内も出ません**。動作確認用と考えてください。

### 方法2: 常用する（推奨・Vercel）

コマンド1つで HTTPS の恒久URLに公開できます。`vercel.json` を用意済みなので設定は不要です。

```bash
npx vercel
```

初回はブラウザが開いてログインを求められます（GitHubアカウント等で数クリック）。
その後、対話で次のように聞かれます。

| 質問 | 答え |
|---|---|
| Set up and deploy? | `y` |
| Which scope? | 自分のアカウントを選択 |
| Link to existing project? | `n` |
| **What’s your project’s name?** | **`kakeibo`**（半角英小文字で入力） |
| In which directory is your code? | `./` |

> **プロジェクト名は必ず手入力してください。** 既定値はフォルダ名（`家計簿アプリ`）が使われますが、
> Vercel のプロジェクト名に日本語は使えないためエラーになります。`kakeibo` などの半角英小文字にしてください。

完了すると `https://kakeibo-xxxx.vercel.app` のようなURLが表示されます。

**本番URLとして確定させる場合**（初回は Preview 扱いになることがあります）:

```bash
npx vercel --prod
```

#### 更新するとき

コードを変更したら、同じコマンドを実行するだけです。

```bash
npx vercel --prod
```

#### 設定してあること（vercel.json）

| 対象 | Cache-Control | 理由 |
|---|---|---|
| `sw.js` | `max-age=0` | 古い Service Worker が残るとアプリを更新しても反映されなくなる |
| `index.html` / manifest | `max-age=0` | 入口は常に最新を取りに行かせる |
| `assets/*` | `1年 immutable` | ファイル名にハッシュが付くので永久キャッシュしてよい |

### 方法3: アカウントを作りたくない場合

ビルド成果物を ZIP にして、<https://app.netlify.com/drop> にドラッグ&ドロップします。

```bash
npm run zip
```

できた `kakeibo-site.zip` を放り込むだけで HTTPS のURLが出ます。
（フォルダを直接ドラッグしてもよいのですが、クリックで開くファイル選択ではフォルダを選べないため ZIP のほうが確実です）

## Android にインストールする

HTTPS のURLをスマホの Chrome で開いたら、

1. 下のタブの **「その他」** をタップ
2. いちばん上の **「このアプリをインストール」** を押す

アプリ内にボタンが出ない場合は、Chrome 右上の **⋮** →
**「アプリをインストール」**（または「ホーム画面に追加」）からでも入れられます。

ホーム画面に緑の¥アイコンが追加され、そこから起動すると全画面表示になり、圏外でも開けます。

> `http://` で開いているとボタンは表示されず、代わりに理由が表示されます。
> Chrome は HTTPS でないとインストールを許可しないためです。
### Android で対応していること

| | |
|---|---|
| **ホーム画面インストール** | 192/512px の PNG + maskable アイコン + manifest |
| **オフライン起動** | Service Worker がアプリ本体をキャッシュ（圏外・機内モードでも開く） |
| **戻るボタン** | シート → 登録画面 → 前のページ の順に1階層ずつ戻る（アプリごと閉じない） |
| **ステータスバー** | `theme-color` で白に統一 |
| **ジェスチャーバー** | `viewport-fit=cover` + セーフエリア対応でタブバーが隠れない |
| **引っ張って更新** | 無効化（誤操作でリロードされないように） |
| **ツールバー開閉** | `dvh` を使い、シートの高さが切れない |
| **レシート撮影** | `capture="environment"` で背面カメラが直接起動 |
| **インストール導線** | `beforeinstallprompt` を捕まえ、「その他」タブにインストールボタンを表示 |

## ネイティブアプリ（APK）について

このリポジトリは **Web / PWA 構成**です（Vercel などに HTTPS で公開し、Android の Chrome から「ホーム画面に追加」で使う）。

以前は Capacitor で APK に包む構成も同梱していましたが、リポジトリを軽く保つため外しました。
APK 化が必要になったら、`dist/` を包むだけなのでいつでも作り直せます。

```bash
npm i -D @capacitor/cli @capacitor/core @capacitor/android
npx cap init Kakeibo jp.kakeibo.app --web-dir dist
npm run build && npx cap add android
npx cap open android   # Android Studio でビルド／実機インストール
```

## 完全オフラインの仕組み（OCR）

既定では tesseract.js は実行ファイルと日本語の学習データを CDN から取りに行きますが、
`npm run ocr:bundle`（`npm run build` に含まれる）が `public/tesseract/` に配置し、
実行時はそちらを使います。

- 学習データは **fast版（2.4MB）** を使用（通常版は15MBあるため）
- 実行ファイルは端末のSIMD対応状況に応じて3変種を同梱
- 同梱が無い環境では自動的に CDN へフォールバック（Webで使う場合の保険）

添付いただいたモックアップに合わせた、ライトテーマ + グリーンアクセントの構成です。

## データ構造

```ts
Expense {                       // 支出
  id, amount, date,             // date は "YYYY-MM-DD"（ローカル日付）
  categoryId, paymentMethod,    // cash | bank | credit | debit | other
  creditCardId?,                // クレカ払いのときのみ
  merchant?, memo?,
  fixedExpenseId?,              // 固定費由来なら、その固定費ID
  excludeFromBudget?,           // 予算計算から外すか
  createdAt, updatedAt?
}

CreditCard {                    // クレジットカード
  id, name,
  closingDay,                   // 締め日（1-28 / 99=月末）
  paymentDay,                   // 支払日（1-28 / 99=月末）
  paymentMonthOffset,           // 0=当月 1=翌月 2=翌々月
  color, archived?
}

Category      { id, name, color, icon, order }
Budget        { id, month, amount }                        // month は "YYYY-MM"
FixedExpense  { id, name, amount, categoryId, paymentDay,
                paymentMethod, creditCardId?, active }
Settings      { income, budgetMode, defaultBudget, ... }   // budgetMode: auto | manual
```

保存キーは `kakeibo:v1`。`schemaVersion` を持ち、`storage/schema.ts` の `migrate()` が
古い・壊れたデータを既定値で補って起動できるようにしています（1世代前のバックアップも自動保持）。

### お金の状態を3つに分けている

混同しやすいので、別々に計算・表示しています。

| | 意味 | 基準 |
|---|---|---|
| **① 今月の使用額** | 今月実際に使った金額 | **利用日** |
| **② カード未払い合計** | カードで使ったが、まだ口座から落ちていない金額 | 引き落とし前すべて |
| **③ 次回引き落とし予定額** | 次の引き落とし1回分 | **引き落とし日** |

さらに ③ は **確定済み**（締め日を過ぎて金額が固まった分）と **未確定**（まだ締め日前で今後増える分）に分けて表示します。

**中身も辿れます。** ダッシュボードのカードをタップすると利用明細が開き、請求サイクル単位で
「この引き落としに何が入っているか」を一覧できます。

```
9/27 引き落とし  [確定]              ¥105,000
8/1〜8/31 の利用分 · 1件

10/27 引き落とし [締め前]            ¥17,700
9/1〜9/30 の利用分 · 4件 · 締め日まで増える可能性があります
  ユニクロ      ¥8,000
  外食          ¥3,500
  セブンイレブン ¥1,200
  Amazon        ¥5,000
```

支払済みの過去の請求も畳んで残してあり、明細内の支出はタップでそのまま編集できます。

> 例: 楽天カード（月末締め・翌月27日払い）で 9/5 に 5,000円使うと
> → 9月の使用額 +5,000円 / 9/30 締め / **10/27 に引き落とし**
> 10/1 に使った分は 10/31 締めなので **11/27 引き落とし**（次々回）に回ります。

### レシート読み取り

支出登録画面の「レシートを読み取る」から撮影すると、金額・日付・店名を読み取って候補を出します。

```
金額の候補（タップで選択）
[ ¥470 合計 ]  [ ¥168 ]  [ ¥160 ]  [ ¥108 ]
日付      9/9
店名の候補  [ セブンイレブン渋谷店 ]
```

**自動では確定しません。** 候補をタップして、必ず通常の登録画面を経由して保存します。読み違えても
その場で直せるようにするためです。カテゴリは読み取れないので自分で選びます。

処理の流れは次のとおりです。

1. 画像を縮小・グレースケール化し、明暗を引き伸ばす（`preprocessImage`）
2. tesseract.js で文字を読む（`recognizeReceipt`）
3. テキストから金額・日付・店名を抽出する（`parseReceipt` — 純粋関数なのでテスト対象）

金額の抽出は「合計 / ご請求額 / お買上計」の行を優先し、**お預り・お釣り・小計・消費税・ポイント・
レジ番号は候補から除外**します。合計が見つからないときは、読み取れた金額を大きい順に候補として並べます。

日本語 OCR は「合 計」「セブ ン イ レブ ン」のように字間へ空白を入れてくるため、
キーワード照合の前に空白を落とし、店名は空白を詰めてから表示しています。

### 固定費と予算の関係

予算モードが `auto` のとき **予算 = 手取り − 有効な固定費合計** です。
固定費はここですでに差し引かれているため、固定費由来の支出は「あと使える金額」から**二重に引かれません**（総支出には含まれます）。

## 現在分かっている制約

- **データはこの端末のブラウザ内（localStorage）にのみ保存されます。**
  ブラウザの履歴削除・シークレットモード・機種変更で消えます。
  月1回など定期的に「その他 → バックアップ → JSONで書き出す」を実行してください。
  （念のため1世代前の状態を自動保持していますが、これも同じ localStorage 内です）
- **端末をまたいだ同期はありません。** PC とスマホでは別データになります。
- **固定費は自動で支出登録されません。** 予算計算（手取り−固定費）にのみ使われます。
  実際の引き落としを履歴に残したい場合は、その都度支出として登録してください。
- **締め日・支払日は 1〜28日 と「月末」から選ぶ形式です。** 29日/30日指定は月によって存在しないため、月末に丸めています。
- **リボ払い・分割払い・ボーナス払いには未対応です。** 利用額は一括で次回請求に計上されます。
- **収入の記録機能はありません。** 「手取り」は予算計算のための1つの数値としてのみ扱います。
- 為替・複数通貨には対応していません（円のみ）。
- **オフライン起動には HTTPS 配信が必要です。** `npm run dev:lan` の http では
  Service Worker が動かないため、インストールもオフライン起動もできません。
- **レシートOCRの精度は「fast版」の学習データによります。** オフライン用に軽い方（2.4MB）を
  同梱しているため、通常版（15MB）よりわずかに精度が落ちます。
  精度を優先したい場合は `scripts/bundle-ocr.mjs` の `LANG_URL` を `4.0.0_fast` から `4.0.0` に変えてください。
- **UIはライトテーマ固定です。** 添付デザインに合わせているため、端末のダークモードには追随しません。
- **レシート読み取りは目安です。** きれいに撮れたレシートなら合計金額はよく当たりますが、しわ・
  感熱紙の退色・斜め撮り・手書きレシートでは外れます。だから自動確定せず候補提示にしています。
  読めるのは金額・日付・店名までで、**カテゴリと明細行は読み取りません**。
- **撮影した画像は保存しません。** 読み取り後に破棄します（localStorage を圧迫させないため）。
  レシート画像を残したい場合は IndexedDB への保存を足す必要があります。
- **OCRの学習データは初回だけ通信します。** 日本語データを CDN から取得し、以後はブラウザに
  キャッシュされます。**レシート画像そのものは端末外に送信されません。**

## 今後追加すると良い機能

**優先度が高いもの**

1. **クラウド同期 / バックアップの自動化**
   Supabase など無料枠のある BaaS に載せると、端末間同期とデータ消失対策が同時に解決します。
   `storage/repository.ts` のインターフェースを実装するだけで差し替えられる設計にしてあります。
2. **固定費の自動登録** — 支払日が来たら支出として自動計上（確認ダイアログつき）
3. **予算のカテゴリ別設定** — 「食費は月3万まで」のような細かい上限
4. **繰り返し支出のテンプレート** — よく使う組み合わせをワンタップ登録

**あると便利なもの**

5. リボ・分割・ボーナス払いへの対応
6. カード利用可能枠の管理と残枠表示
7. 週次サマリの通知（PWA Push）
8. CSV インポート（銀行・カード明細の取り込み）
9. 支出の検索・絞り込み（金額帯、店名、期間）
10. 年間集計・年またぎの比較

**MVP完成後に検討としていたもの**（未着手）
銀行口座/クレカ自動連携・AI支出分析・家族共有・複数ユーザー・SNS機能
